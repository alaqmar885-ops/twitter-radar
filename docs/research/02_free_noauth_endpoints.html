1. Headline finding: 4 free endpoints that actually work

Before you install any scraper at all, know this: there are undocumented (and one official) X endpoints that return structured tweet JSON with no API key, no login, and no cost. I tested all of them live.

EndpointAuthReturnsStatus
Syndication API
cdn.syndication.twimg.com/tweet-result?id={id}&token=0		 None Full tweet JSON: text, author, like count, reply count, lang, created_at, entities, nested parent tweet, quoted tweet, edit_control Verified 200
FxTwitter (FxEmbed)
api.fxtwitter.com/{user}/status/{id}		 None Richest free payload found: text, raw_text w/ facets, author followers / following / likes / media_count / bio, media, quotes Verified 200
FxTwitter profile
api.fxtwitter.com/2/profile/{handle}/statuses		 None A user's timeline as JSON — free, no login. (This is the rare "no-account timeline" find.) Verified 200
Official oEmbed
publish.twitter.com/oembed?url=…		 None — official HTML embed block, author_name, author_url, provider. Limited fields but sanctioned by X and effectively unlimited Verified 200
vxtwitter api.vxtwitter.com None — Cloudflare blocked

✅ Why the Syndication API matters most

It's the endpoint that powers embedded tweets on third-party sites, it's on a CDN (cdn.syndication.twimg.com), and it's far more tolerant than x.com itself. When you fetch a reply, the response includes a parent field with the full parent tweet object — so 2 fetches give you a complete 3-tweet thread. It even works with curl's default User-Agent (no browser spoofing needed).

4. The anti-detect browser layer (free)

Raw Playwright gets flagged instantly in headless mode. These free projects patch that — and they're the difference between a scraper that works and one that 403s.

Camoufox / Camofox Strongest

A Firefox fork with C++-level fingerprint patches — deeper than JS-based stealth because the spoofing happens below the JS layer. Camofox wraps it as a REST browser server for AI agents. Default driver in x-tweet-fetcher.

Patchright Drop-in

Patched, undetected version of Playwright — a drop-in replacement that automatically removes automation traces. Recommended for Python users who want the Playwright API unchanged. Caveat: auto-deploys chase Playwright releases, so bugs can appear after upstream changes.

playwright-stealth

JS-level evasion patches (navigator.webdriver, plugins, languages, etc.). Lighter than Camoufox, easier than Patchright, but shallower — C++-level patches beat JS-level ones against serious fingerprinting.

TLS-fingerprint layer (lighter alternatives to a full browser)

If you don't need JS rendering, spoofing the TLS handshake is often enough — far cheaper than a headless browser:

  • curl_cffi (Python) — impersonates real browser TLS/JA3 signatures. Used by twscrape (via twscrape[curl]) and twifork (via twifork[impersonate]).
  • CycleTLS (Node) — same idea; used by @the-convocation/twitter-scraper to dodge Cloudflare 403s on login.
  • Scrapling's StealthyFetcher — adaptive, bypasses Cloudflare Turnstile without brittle selectors.

twifork (PawiX25 / MaayanLab) New find — use this over twikit

github.com/PawiX25/twifork · MIT · updated Jun 2026

Drop-in twikit replacement Fixes 15+ upstream bugs Optional TLS impersonation No API key

Critical find: upstream twikit==2.3.3 on PyPI is broken in multiple ways in 2026. twifork fixes them and still imports as twikit, so from twikit import Client keeps working unchanged.

What it fixes

  • ClientTransaction / "Couldn't get KEY_BYTE indices" — updated ondemand.s.js parsing for the new X webpack bundle
  • Sticky 404s on SearchTimeline and friends/list (missing frame_time rounding in the transaction-id animation key)
  • KeyError on missing optional fields; empty user name/screen_name (X moved fields out of legacy)
  • get_tweet_by_id KeyError: 'itemContent'; get_user_tweets crash on empty timelines
  • get_trends deprecated → rebuilt on GenericTimelineById, plus new get_explore_page()
  • RecursionError on rate-limit; GuestClient.activate() 404; captcha unlock path

8. Self-hosted stacks & the Nitter revival

Public Nitter instances are unreliable — but self-hosting changes the calculus, and several tools above are built around exactly that.

# One command, then point tools at it

docker run -d -p 8788:8080 --name nitter zedeus/nitter:latest


# x-tweet-fetcher with failover across instances

export XTF_NITTER=http://127.0.0.1:8788,https://your-backup-instance.example

xtf --user elonmusk --limit 20

Why bother: Nitter serves static HTML with no JS and no anti-bot — trivially scrapable with BeautifulSoup. The failure mode shifts from "does X block me" to "do I keep my instance alive."

  • Realistic ceiling: self-hosting requires a pool of guest accounts + proxies; failure rate in production is high. Treat it as a backend of last resort / secondary source, not your primary pipeline.
  • Best pattern: router with failover (x-tweet-fetcher does this natively) — Nitter first, browser fallback, never a silent empty result.

    with sync_playwright() as pw:

        b = pw.chromium.launch(proxy={"server": PROXY})  # residential!

        calls = []

        page = b.new_page()

                if "UserTweets" in r.url or "TweetResultByRestId" in r.url else None)

12. Risks, limits & honest caveats

⚠️ What will bite you

  • Undocumented endpoints can vanish. The Syndication API and FxTwitter are unofficial. FxTwitter is a volunteer service. Build with fallbacks, not a single point of failure — this is exactly why x-tweet-fetcher's router design is smart.
  • Handle TweetTombstone. Syndication returns HTTP 200 with a tombstone for deleted/suspended accounts. Naive code will crash or ingest junk.
  • Timelines ≠ single tweets. The tweet endpoint was rock solid in testing; the timeline-profile variant returned 429 from a datacenter IP. Don't assume parity.
  • Datacenter IPs are poison for x.com itself. Fine for CDN/syndication endpoints; fatal for browser automation. Budget for residential proxies (~$15/GB) if you go the Playwright route.
  • Account-based tools carry ban risk. twscrape, twifork, Scweet, @the-convocation all use real sessions. Use a throwaway account, pace requests, rotate.
  • Maintenance is the real price. Guest tokens, doc_ids, and transaction IDs rotate every 2–4 weeks. "Free" ≠ zero cost — budget 10–15 hrs/month for a DIY pipeline.
  • ToS: public scraping is generally legal in the US (hiQ v. LinkedIn) but breaches X's Terms — which specify liquidated damages of $15,000 per 1M posts accessed in 24h. GDPR applies to EU personal data. Not legal advice — but don't ignore it.

✅ Bottom line

You probably don't need to pay. Start with the free endpoints (Syndication for threads, FxTwitter for rich single tweets + free timelines, oEmbed for official sanction) — they cover a surprising amount with zero setup. Reach for twifork or twscrape when you need search, followers, or volume. Reach for a Camoufox/Patchright + GraphQL-interception browser stack when you need anything X gates behind a session. And always wire in at least one fallback — the single most common failure in this space is trusting one endpoint to stay up.
