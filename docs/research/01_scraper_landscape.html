1. The 2026 landscape & what changed

Scraping X (formerly Twitter) is harder than it has ever been. Three structural shifts since 2023 reshaped the ecosystem:

  • The free API was killed. X gutted legacy free tiers in Feb 2023; as of 2026 there is no free read tier — the free allowance is write-only (1,500 posts/mo). Reading tweets starts at $200/mo.
  • Anonymous guest access was locked down. X now requires guest tokens tied to IP and (since Jan 2025) browser fingerprints. This single change killed the entire free-library stack.
  • Aggressive anti-bot detection. Datacenter IPs are blocked within 1–2 requests; TLS fingerprinting, doc_id rotation every 2–4 weeks, and tighter cookie validation make DIY scrapers a permanent maintenance burden.

The practical effect: the once-dominant free tools (snscrape, Twint, Nitter) are now described by practitioners as "a graveyard." Surviving open-source tools all require logged-in accounts, which introduces suspension risk. The trade-off is now: pay money, pay with account-ban risk, or pay with 10–15 hrs/month of maintenance.

3. Open-source Python libraries (free, account-based)

All surviving free libraries bypass the official API by calling X's internal GraphQL endpoints using logged-in account sessions. This means: no API key, but account suspension risk with aggressive use.

twscrape Top pick

github.com/vladkens/twscrape · ⭐ 2.8k · Python · Actively maintained (last commit Aug 2026, v0.20.1)

Async Python library and CLI for X/Twitter Search and GraphQL endpoints. The most robust free option, designed for production.

Multi-account rotation Built-in rate-limit handling SQLite session storage Per-account proxies CLI + Python API Needs login/cookies

What it can scrape

  • Search: tweets, users, trends (Top / Latest / Media tabs)
  • Tweets: details, replies, threads, retweeters, bookmarks
  • Users: by id/login, about, following, followers, verified followers, subscriptions
  • Timelines: user_tweets, user_tweets_and_replies, user_media
  • Lists & Communities: timelines, members, moderators, info
  • Trends by category (news, sport, entertainment)

Key mechanics

  • Runs on your own account pool — rotate accounts when one hits a rate limit.
  • Most stable setup: add accounts from browser cookies (auth_token + ct0), exported via the unjar tool.
  • Optional curl-cffi backend for browser-like TLS fingerprinting (recommended to evade detection).
  • Returns SNScrape-compatible parsed models or raw API responses.
  • limit = target object count, not page size (X controls page size). user_tweets capped at ~3,200 by X.

github.com/d60/twikit · ⭐ 4.7k · Python · Updated Mar 2026

The most-starred free option. A simple API wrapper around Twitter's internal API — no API key required, but requires login with username/email/password and manages session cookies.

5. Browser automation & AI agents

Playwright + GraphQL interception Most robust DIY

The most resilient programmatic approach in 2026: use a real headless browser to load X.com pages, then intercept the XHR/fetch calls to GraphQL endpoints (UserTweets, TweetResultByRestId) and extract clean JSON directly — no brittle CSS selectors, no manual doc_id tracking.

  • Why it survives: the browser requests its own current doc_ids, so you never hardcode rotating identifiers.
  • Open-source reference: scrapfly/scrapfly-scrapers/twitter-scraper and Proxidize's open-source Playwright scraper.
  • Cost: free code, but requires residential proxies (~$15/GB) to prevent IP bans during infinite scroll.
  • Maintenance tax: ~10–15 hrs/month re-fixing when X changes defenses.
from playwright.sync_api import sync_playwright


with sync_playwright() as pw:

    browser = pw.chromium.launch(

        proxy={"server": "http://residential-proxy:8000"}

    )

    page = browser.new_page()

    page.goto("https://x.com/x")

    page.wait_for_selector("[data-testid='primaryColumn']")

    # then capture XHR calls to UserTweets / TweetResultByRestId

Browser Use Cutting-edge

Open-source AI agent framework that automates browser interactions via natural-language prompts. Instead of selectors or network scripts, you instruct it: "go to my Twitter and extract the latest tweets into a Google Sheet."

Custom Chromium fork (C++/OS stealth patches) Bypasses Cloudflare/Akamai/DataDome (81% stealth success) Built-in CAPTCHA solving Handles SPAs, popups, infinite scroll Slower & costlier (full browser + LLM calls)

Best when X is a dynamic SPA requiring human-like interaction and you want zero selector maintenance. Tools like Firecrawl and BeautifulSoup fail outright on X's anti-bot; Browser Use operates like a human user.

Scrapling

Newer adaptive scraping framework with a StealthyFetcher that natively bypasses Cloudflare Turnstile/Interstitials by spoofing Chromium fingerprints. General-purpose — you write X-specific parsing logic yourself. Good for multi-session scraping.

8. How X's hidden API works (and why scrapers break)

X.com's web app is a GraphQL client. Every profile/timeline you see is fetched from a hidden internal API behind three rotating guards:

Guest tokens
Temporary session credentials, expire in hours, tied to requesting IP (and since Jan 2025, browser fingerprint). Without one → no queries. This is what killed the free libraries.
doc_ids
Unique identifiers for each GraphQL operation (fetch profile, get tweet, load timeline). Rotated every 2–4 weeks. A scraper tracks 8–12 at once; rotation breaks hardcoded queries silently.
Rate limits + IP
Anonymous access ~300 req/hr. Datacenter IPs blocked within 1–2 requests. Residential proxies are effectively mandatory.
TLS fingerprinting
X inspects TLS handshake to detect non-browser clients — hence twscrape's optional curl-cffi backend and Browser Use's custom Chromium fork.

What you can reach without login: public profiles, individual tweets + visible replies, public engagement counts, embedded media metadata. Login-gated: protected accounts, DMs, full follower/following lists, keyword & timeline search. (Workaround for finding tweet URLs without login: site:x.com inurl:status <keyword> on Google — but Google's index lags real-time by hours/days.)

9. Legal & Terms-of-Service considerations

⚠ Read this before scraping

  • US legality: Scraping public Twitter data is generally legal under the hiQ v. LinkedIn ruling (accessing public web data ≠ CFAA violation).
  • But it breaches X's Terms of Service — a contract issue, not a crime. X's ToS imposes liquidated damages of $15,000 (or €15,000 in EU/EFTA/UK) per 1,000,000 posts accessed within 24 hours.
  • CFAA line you don't cross: don't touch protected accounts, DMs, or anything behind a login.
  • EU/GDPR: public posts can still contain personal data — GDPR applies when you store/process it.
  • Safe-ground rules: public data only · don't hoard · respect rate limits · don't overload servers.

This is informational, not legal advice. Consult a lawyer for your specific case.

Bottom line

There is no single "best" tool — the right choice depends on your volume, budget, uptime tolerance, and willingness to maintain. The free-library era is over; in 2026, working Twitter scraping means one of three real trade-offs: pay money (managed API), pay with account-ban risk (session-based libs like twscrape/twikit), or pay with ~10–15 hrs/month of maintenance (DIY Playwright + residential proxies). For production pipelines that can't afford weekly breakage, a maintained scraper API (Scrapfly/Bright Data/twitterapi.io) is the pragmatic choice.
